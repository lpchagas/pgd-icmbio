# I11 — Percentual de Avaliações Excepcionais


> **Decisão CGOV D12 (13.09.2026) — cálculo bruto mantido, volumetria
> exportada.** O percentual continua sendo calculado sobre a categoria bruta
> (`sequencia = 1`, Excepcional), sem ponderação. Acrescenta-se a coluna
> **`volume_suficiente`** (1 quando a unidade tem ao menos 5 avaliações no
> período, 0 abaixo disso), para que o BI trate com reserva as unidades de
> amostra pequena. Nenhuma linha é suprimida.

## 1. Finalidade do indicador

O I11 calcula a **proporção de avaliações de Planos de Trabalho classificadas como “Excepcional”** em relação ao total de avaliações de PT da unidade no período. No PETRVS, essa categoria é armazenada como `tan.sequencia = 1` e equivale ao score convertido 5.

Enquanto o I10 monitora o extremo negativo da distribuição de avaliações, o I11 olha para o extremo positivo: qual é o peso das avaliações que formalmente reconheceram desempenho acima do esperado, com diferencial de qualidade?

A pergunta central que o I11 responde é: **"Qual percentual dos Planos de Trabalho avaliados no período foram classificados como 'Excepcional'?"**

O indicador é intencionalmente simétrico ao I10 — os dois formam um par analítico. Lidos juntos, revelam como a escala de avaliação está sendo usada nas extremidades: se poucos chegam ao topo e poucos chegam ao fundo, a distribuição é conservadora; se muitos chegam ao topo e muitos chegam ao fundo, a distribuição é polarizada; se quase todos chegam ao topo, há um sinal de avaliação por leniência (grade inflation).

Esse par I10-I11 tem uma característica importante que a média do I09 não captura: **a média pode ser a mesma em distribuições completamente diferentes**. Uma unidade com todos os servidores no score 3 tem a mesma média que uma unidade com metade no score 1 e metade no score 5 — mas os dois perfis exigem respostas de gestão completamente distintas.

O I11 permite:

- Identificar unidades com genuíno reconhecimento de excelência;
- Detectar possível uso inflacionado da nota máxima (avaliação por cordialidade);
- Comparar a distribuição de destaque entre unidades e entre ciclos;
- Cruzar com o I12 para verificar se o reconhecimento individual (PT) é coerente com a avaliação coletiva (PE) da mesma unidade.

> **Regra confirmada nesta base:** “Excepcional” corresponde a `tan.sequencia = 1`. Consulte o [Eixo 4](06.4-eixo4.md) para a escala completa.

## 2. Consulta completa (Denodo VQL)

Execute no DBeaver (conexão Denodo `petrvs_icmbio`) ou via Python/JDBC. Ajuste apenas `data_inicio` e `data_fim` no bloco `parametros`.

```python
SQL_I11 = """
WITH parametros AS (
    SELECT
        CAST('{ini}' AS DATE) AS data_inicio,
        CAST('{fim}' AS DATE) AS data_fim,
        0                     AS incluir_excluidos
),
avaliacoes_pt AS (
    SELECT
        av.id          AS id_avaliacao,
        pt.unidade_id,
        pt.usuario_id  AS id_servidor,
        tan.sequencia  AS sequencia_nota
    FROM petrvs_icmbio_avaliacoes av
    JOIN petrvs_icmbio_planos_trabalhos_consolidacoes ptc
        ON ptc.id = av.plano_trabalho_consolidacao_id
    JOIN petrvs_icmbio_planos_trabalhos pt
        ON pt.id = ptc.plano_trabalho_id
    JOIN petrvs_icmbio_tipos_avaliacoes_notas tan
        ON tan.id = av.tipo_avaliacao_nota_id
    CROSS JOIN parametros p
    WHERE av.plano_trabalho_consolidacao_id IS NOT NULL
      AND (p.incluir_excluidos = 1 OR av.deleted_at IS NULL)
      AND CAST(av.data_avaliacao AS DATE) BETWEEN p.data_inicio AND p.data_fim
      AND CAST(pt.data_inicio AS DATE) <= p.data_fim
      AND CAST(pt.data_fim   AS DATE) >= p.data_inicio
      AND (p.incluir_excluidos = 1 OR pt.deleted_at IS NULL)
),
proporcao_por_unidade AS (
    SELECT
        COALESCE(un.sigla, 'N.I.')                                   AS unidade_sigla,
        COALESCE(un.nome,  'N.I.')                                   AS unidade_nome,
        COUNT(avpt.id_avaliacao)                                     AS total_avaliacoes_pt,
        COUNT(DISTINCT avpt.id_servidor)                             AS total_servidores_avaliados,
        SUM(CASE WHEN avpt.sequencia_nota = 1 THEN 1 ELSE 0 END)    AS qtd_excepcional,
        ROUND(
            SUM(CASE WHEN avpt.sequencia_nota = 1 THEN 1 ELSE 0 END) * 100.0
                / NULLIF(COUNT(avpt.id_avaliacao), 0),
            2
        )                                                            AS perc_excepcional
    FROM avaliacoes_pt avpt
    LEFT JOIN petrvs_icmbio_unidades un ON un.id = avpt.unidade_id
    GROUP BY COALESCE(un.sigla, 'N.I.'), COALESCE(un.nome, 'N.I.')
)
SELECT
    unidade_sigla,
    unidade_nome,
    total_avaliacoes_pt,
    total_servidores_avaliados,
    qtd_excepcional,
    perc_excepcional,
    CASE
        WHEN perc_excepcional >= 40 THEN 'Reconhecimento elevado'
        WHEN perc_excepcional >= 20 THEN 'Desempenho diferenciado'
        WHEN perc_excepcional >=  5 THEN 'Destaque pontual'
        ELSE 'Escala subutilizada'
    END AS nivel_reconhecimento
FROM proporcao_por_unidade
ORDER BY perc_excepcional DESC, unidade_sigla
"""
```

> **Regra de escala:** I11 testa diretamente `tan.sequencia = 1`. A conversão `6 - tan.sequencia` aparece somente nos indicadores que calculam média (I09 e I12).

---

## 3. Passos da consulta

1. `parametros` recebe `{ini}` e `{fim}` do script canônico.
2. `avaliacoes_pt` seleciona avaliações ativas pela data de negócio
   `av.data_avaliacao`, preserva `tan.sequencia` sem conversão e confirma a
   sobreposição da vigência do PT.
3. `proporcao_por_unidade` conta todas as avaliações no denominador e somente
   `sequencia_nota = 1` no numerador. Também calcula servidores distintos para
   o limiar de anonimização.
4. O `SELECT` final aplica faixas interpretativas, sempre lidas junto com I09,
   I10, I12 e o volume avaliado.

A fórmula é:

```text
perc_excepcional = avaliações com sequencia = 1 / total de avaliações de PT × 100
```

Na escala bruta, `sequencia = 1` representa “Excepcional”. Quando I09 e I12
precisam calcular médias, `6 - sequencia` converte essa categoria no score 5;
I11, porém, testa diretamente a sequência bruta.

## 4. Como interpretar o resultado

### Estrutura do resultado

| Coluna | O que informa |
| --- | --- |
| `unidade_sigla` / `unidade_nome` | Identidade da unidade |
| `total_avaliacoes_pt` | Base total de avaliações — o denominador |
| `qtd_excepcional` | Número absoluto de avaliações classificadas como `Excepcional` |
| `perc_excepcional` | Percentual do total — o indicador central |
| `nivel_reconhecimento` | Classificação provisória do padrão observado |

### Exemplo com dados do ICMBio

Resultado hipotético de 2025 (mesmas unidades dos exemplos I09 e I10):

| unidade_sigla | total_avaliacoes_pt | qtd_excepcional | perc_excepcional | nivel_reconhecimento |
| --- | --- | --- | --- | --- |
| CGOF | 52 | 13 | 25.00 | Desempenho diferenciado |
| COGEO | 38 | 5 | 13.16 | Destaque pontual |
| CGOV | 45 | 5 | 11.11 | Destaque pontual |
| DIREC | 12 | 0 | 0.00 | Escala subutilizada |
| AUDIT | 18 | 0 | 0.00 | Escala subutilizada |

**Leitura caso a caso:**

**CGOF — Desempenho diferenciado (25%):** 13 das 52 avaliações com nota máxima. Combinando com o I09 (média 4.12) e o I10 (5.77% de inadequados), o perfil da CGOF é consistente: unidade com distribuição de avaliações inclinada para o topo, diferenciação real de notas e poucos casos de inadequação. O I11 aqui reforça a leitura do I09 — não é apenas média alta, é também concentração de excelência reconhecida.

**DIREC — Escala subutilizada (0%):** nenhuma avaliação classificada como “Excepcional”. Combinando com I09 (média 2.42) e I10 (33.33% de inadequados), o quadro da DIREC é o oposto da CGOF: os avaliadores não estão reconhecendo excelência porque, de fato, ela não está sendo observada — ou os critérios para o conceito “Excepcional” são muito exigentes. Não há ambiguidade aqui: I11 baixo + I10 alto + I09 baixo formam um padrão coerente de dificuldade.

**AUDIT — Escala subutilizada (0%), mas por razão diferente:** a AUDIT também tem I11 zerado, mas pelo motivo oposto da DIREC: conforme observado no I09, todas as 18 avaliações foram nota 3. A ausência do conceito “Excepcional” não é sinal de mau desempenho — é sinal de avaliação padronizada. O diferencial entre AUDIT e DIREC só fica claro quando os três indicadores (I09, I10, I11) são lidos juntos.

### A leitura combinada I10 + I11: o mapa de distribuição

Os dois indicadores juntos revelam o **perfil de uso da escala** de cada unidade. Quatro padrões principais:

| Perfil | I10 | I11 | Interpretação |
| --- | --- | --- | --- |
| Diferenciado | Baixo | Alto | Poucos inadequados, muitos excepcionais — desempenho genuíno ou possível leniência (verificar I12) |
| Polarizado | Alto | Alto | Muitos inadequados e muitos excepcionais — distribuição bimodal, equipe dividida em extremos |
| Problemático | Alto | Baixo | Muitos inadequados, nenhum excepcional — dificuldades sistêmicas reconhecidas |
| Conservador | Baixo | Baixo | Poucos nas extremidades — uso restrito da escala, sem diferenciação (como AUDIT) |

O padrão "Conservador" é o mais comum em organizações que estão começando a usar o PGD como instrumento de gestão de desempenho, e não apenas como controle de frequência. A evolução esperada ao longo dos ciclos é que o perfil migre do "Conservador" para o "Diferenciado" — com crescimento de I11 representando reconhecimento genuíno e redução de I10 representando menor incidência de desempenho inadequado.

### Como distinguir excelência genuína de leniência avaliativa

Um I11 elevado pode ter duas origens. Para identificar qual delas prevalece, cruze com o I12:

**Cenário A — Excelência genuína:** I11 alto **e** I12 com baixa divergência (PE e PT com médias próximas). Os gestores avaliam bem os PTs individuais e a avaliação coletiva do PE confirma essa percepção — o desempenho é de fato alto nos dois ângulos.

**Cenário B — Leniência avaliativa:** I11 alto **e** I12 com alta divergência (PE com média significativamente menor que PT). Os gestores avaliam bem os PTs individualmente, mas reconhecem, na avaliação coletiva do PE, que os resultados da unidade não foram tão excepcionais. Isso é o sinal clássico de "avaliação por cordialidade" — o gestor não quer prejudicar o servidor individualmente, mas no nível coletivo tem que reconhecer que a unidade não atingiu o padrão que as notas individuais sugerem.

## 5. Tabelas da base utilizadas

- `avaliacoes` — registros de avaliação.
- `planos_trabalhos_consolidacoes` — para mapear avaliações de PT ao `plano_trabalho_id`.
- `planos_trabalhos` — para obter `unidade_id` da consolidação.
- `tipos_avaliacoes_notas` — escala de notas (`sequencia` 1–5).
- `unidades` — para nome e sigla da unidade.

## 6. Dicionário de dados (colunas do CSV)

| Coluna | Descrição |
| --- | --- |
| `unidade_sigla` | Sigla padronizada da unidade. |

| `mesogrupo` | Agrupador intermediário da estrutura organizacional do ICMBio (ex.: "Presidência", "DIPLAN", "UC na GR2"). Não vem da SQL — inserido por pós-processamento Python logo após `unidade_nome`, cruzando `unidade_sigla`/`unidade_nome` com as planilhas de estrutura mantidas pela CGOV (ver [`lib/estrutura_organizacional.py`](../../lib/estrutura_organizacional.py)). | `perc_excepcional` | Percentual de avaliações classificadas como `Excepcional`, arredondado a 2 decimais. |
| `nivel_reconhecimento` | Classificação qualitativa: `Reconhecimento elevado`, `Desempenho diferenciado`, `Destaque pontual`, `Escala subutilizada`. |
